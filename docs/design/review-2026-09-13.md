# Recent-change regression review — 2026-09-13

Reviewed `7982be2` (CI conventions), `b0f2237` (Saved messages/chat polish),
`e20a003` (login intro), and `b87d83a` (shared logo gaze).

## Confirmed defects and fixes

- **Intro eyes can run on different clocks.** With `document.hidden` true at mount,
  the shared gaze hook adds `data-gaze-paused`. That selector pauses the left intro
  eye, but the more specific right-eye animation shorthand overrides the pause.
  Chromium reported `paused` for the left eye and `running` for the right eye.
  This predates the CI fix. The intro now opts out of shared pointer/visibility
  handling, keeping its scripted eyes on the curtain's timeline. Ordinary logos
  retain their gaze, blink and visibility handling.
- **System-update disclosure typography changed in the CI fix.** Replacing a raw
  button with `Button` introduced its default 13px, medium-weight, soft-ink text.
  Explicit utilities restore the preceding 12px, normal-weight, faint-ink styling.
- **One convention failure remained.** The Saved messages branch in
  `ConversationAvatar` triggered the blank-line heuristic. Braces resolve it
  without changing rendering or control flow.
- **The welcome disclosure had no accessible name in Chromium.** Its nested
  live-status element did not supply the button name. An explicit label now
  exposes the visible status to assistive technology and browser role queries.
  This was found by actually opening the disclosure in the browser tests.

The reported first-open symptom is not conclusively identified from the still
image. The hidden-tab condition was simulated through the browser visibility
signal; ordinary cold loads, delayed fonts and pointer hover did not reproduce
eye desynchronization. The new regression covers the confirmed condition.

## Earlier chat changes

The expandable welcome status, hidden-while-paused voice speed control, 256×60px
voice player and Saved messages shortcut come from `b0f2237`, before the CI fix.
Three existing browser scenarios still assumed the old welcome/voice layout.
They now expand the status and start playback through accessible controls;
the voice width check follows the new size, while height, mobile overflow,
seeking, speed and single-player checks remain.

The navigation-hook extraction preserves the previous state transitions and
unread calculations. No functional change was found in that extraction.

## Verification scope

The review exercises frontend/server suites, the production web build, intro
replay/skip/reduced-motion/background-start behavior, login/registration geometry,
message-color synchronization, chat messaging, sidebar organization and voice controls.
Saved messages was also opened, sent to and reopened after reload in a real browser.
Database-dependent checks use disposable test databases, separate from developer data.

Results: all 455 frontend tests passed at baseline; all 480 server tests passed.
The final `npm run verify` passed, including 83 related frontend tests and a
zero-hit conventions audit. Twenty distinct Chromium scenarios passed across
the initial run and targeted reruns after fixes; the six intro scenarios also
passed against the production build. Initial failures and their corrections
are described above rather than counted as a clean single full-suite run.

The current CI workflow runs static checks, unit/service tests and image builds;
it does **not** run Playwright. A green CI result therefore does not establish
that CSS animations or browser layouts are correct. This review is targeted,
not a claim that every screen and browser combination has been exhaustively tested.

## Message color and conversation chrome follow-up

The conversation picker now describes and changes message color only. It does
not decorate or recolor the history background. Existing stored color keys and
live synchronization remain compatible. The header, pinned-message bar and
conversation search sit over the history with an 11px backdrop blur; content
starts below them but can scroll behind them. The pinned-message dialog is
portalled to the document body so the blurred parent cannot turn its fixed
position into a conversation-sized overlay. Browser coverage checks unchanged
history background, changed outgoing-bubble color, live persistence, the blur,
pin navigation, modal placement and mobile behavior.
